Platform

Serverless GPU inference at a million images a month

  • 93% cheaper per image than the fleet it replaced
  • 6,669 images/hr sustained
  • 216K images delivered in 24h
  • 5-way parallel GPU fan-out

Four greenfield platforms — image, 3D, AutoQC and 360 — on one event-driven backbone: SQS into an EventBridge Pipe, into Step Functions, into AWS Batch across Fargate CPU and EC2 GPU. Each is its own Terraform monorepo with per-AZ workspace isolation, a three-pool A10G / L4 / L40S GPU topology, Triton inference sidecars, and an SSM-backed AMI registry that turns a GPU image roll into a two-parameter change. It replaced an always-on GPU fleet.

Kubernetes

Putting GPU inference on Kubernetes

  • Images Realtime live on EKS
  • EKS 1.36 + Karpenter for Food
  • On-Demand for sync, Spot for async
  • KEDA on in-flight requests and queue depth
  • Async scales to zero when idle

GPU capacity, not code, kept capping image throughput — one day there was no g6.2xlarge left in three availability zones for three and a half hours. So realtime GPU inference moved from ECS onto EKS. I stood up the first cluster myself (EKS 1.36 with Karpenter, for Food’s UAT environment), then brought in an AWS implementation partner for the shared GPU module, reviewed it line by line against our workloads, and closed the gaps with them: no metrics collector, HTTP-only ingress, subnet tags our VPC module would strip, no GitOps. Karpenter launches GPU nodes only when pods are waiting; KEDA scales sync models on in-flight requests and async workers on queue depth, down to zero. Images Realtime now runs on it in production.

Foundations

One landing zone, one network, every account as code

  • 24 accounts onboarded in Terraform
  • SOC 2-aligned access tiers, SAML + MFA
  • Transit Gateway hub-and-spoke
  • 617-resource 360 platform, 2 regions

When the estate outgrew a single account, I built the foundation it moves onto: IAM Identity Center and every account baseline as Terraform, with SAML, MFA and SOC 2-aligned role tiers, then a Transit Gateway hub-and-spoke — RAM-shared, separate prod and non-prod route tables, east-west only — that links the new workload accounts to legacy production. The 360 processing platform runs there in its own accounts: Step Functions into AWS Batch across five compute pools in two regions, plus a realtime tier on GPU ECS.

Security

Shipping edge controls without breaking production

  • 242K requests analysed before enforcing
  • Zero production impact at rollout
  • Multi-account Identity Center as code
  • Foundation for SOC 2 and GDPR

Authentication controls at the edge, on the WAF in front of our public load balancer. I rolled them out the careful way — running the rule in observation mode across a quarter of a million real requests and reading the results before enforcing anything, which is how I caught a legacy dependency a straight cutover would have broken. Alongside it, Project Shield ended shadow IT by moving internal and agentic applications onto governed, Terraform-only AWS with business-unit segregation.

Reliability

From firefighting to an operating model

  • Monthly incident volume down ~85%
  • Recovered an EKS outage, all 43 models restored
  • Global Accelerator failover during the Cloudflare outage
  • ~1,400 LOC, 62+ tests

The function was absorbing four to five incidents a day — a support queue, not a platform team. The worst of them, a model-serving outage, traced back to etcd running out of space after 345 days without compaction. I rebuilt the function around on-call rotations with per-team schedule sync, real RCA discipline, branch protection and merge governance, a deployment freeze policy, and golden-path deployment docs. Then I automated the lifecycle: a PagerDuty to Jira to Slack pipeline with fingerprint deduplication, a reopen window, and automatic RCA ticketing.

Cloud economics

Making the bill stop growing

  • Growth curve flattened to +0.9%
  • Bill 14% lower, Sep → Oct 2026
  • 360 cost per artifact ~33% lower
  • 236.8M S3 objects deleted, zero errors
  • Per-batch and per-image cost instrumented
  • Multi-year AWS EDP commitment

Spend had been climbing 8–10% every single month. Rather than trimming line items, I went after the structure: retired a GPU service outright, downsized GPU tiers while holding throughput, killed a 35-million-message queue pendency loop before it reached the invoice, and co-located hot-path storage in a single AZ to remove cross-AZ transfer entirely. Then I audited the hourly Cost and Usage Report line by line, separated committed spend from what could actually move, and worked through the list — compute caps, ECR lifecycle across 347 repositories, and a zero-error deletion of 236.8 million S3 objects from a 1.15 PiB estate. Moving 360 processing onto serverless batch cut its cost per artifact by a third, and the bill fell 14% from September to October 2026. I also built the infrastructure and usage case behind a multi-year AWS Enterprise Discount Program commitment, with our finance team and CTO.

Regulated FinTech

Shift-left security, published

  • Security testing 2–3 days → ~35 min
  • 75% fewer security incidents
  • Terraform-defined pipeline, open-source tooling
  • Read the write-up →

At SMC Global Securities — a SEBI-regulated broking platform — I helped build an in-house DevSecOps pipeline inside AWS CodePipeline, defined end to end in Terraform: dependency scanning, static analysis, secret detection, container scanning, dynamic testing against the running application and port scanning, with every finding aggregated into Security Hub. It replaced a process where security review happened after QA, by which point fixes were expensive and releases were already late. The engineering write-up was published on SMC's tech blog, co-authored with the CPTO and the Director of Cloud Engineering.
